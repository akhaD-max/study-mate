# Задача 025: MVP профиля студента

- Цель: реализовать профиль по `StudyMate_Profile_MVP.md`, прочитанному целиком
  из Downloads владельца задачи, с учётом US-02 и существующей архитектуры.
- Ответственный за постановку, функциональную проверку и передачу на ревью:
  владелец текущей задачи; исполнитель: Codex. Ревью схемы и миграций — Денис.
- Ветка: `feat/025-user_profile`, база: актуальная `origin/main` (`ac0f815`).
  Номер 025 — локальный номер этой работы, а не подтверждённый номер backlog.
- Приёмка: просмотр своего и чужого профиля после входа; редактирование только
  своего; обязательные вуз, специальность, курс 1–6 и 1–15 уникальных навыков;
  необязательные имя, специализация и описание до 1000 символов; PostgreSQL;
  отсутствие email в карточке; заглушка аватара; ссылки из навигации и заявок.
- Область: `accounts` (модели, формы, сервис, views, URL, шаблоны, admin,
  последовательные миграции), подключение `/profile/` в `config/urls.py`,
  ссылки в существующих шаблонах проектов/заявок, `static/js/profile.js`,
  документация задачи, отчёт и описание PR. CSS не добавляется.
- Зафиксированные для реализации имена: `accounts.Skill`,
  `accounts.Specialization`, поля `User.university`, `specialty`, `course`,
  `bio`, `desired_role`, `skills`; `ProfileForm`; `update_profile`;
  namespace `profiles`, маршруты `/profile/`, `/profile/edit/`,
  `/profile/<uuid:user_id>/`. Совместимые ссылки `/accounts/profile/…`
  обслуживаются теми же обработчиками через `accounts:profiles:*`.
- Шаблоны: `accounts/profile_base.html`, `profile_detail.html`,
  `profile_edit.html`; контекст просмотра `profile_user`, `is_owner`,
  `profile_is_empty`; редактирования — `form`, `cancel_url`. HTMX-фрагментов,
  targets и событий для профиля нет, обычные HTML GET/POST + CSRF.
- Зависимости: уже существующие `accounts.User`, auth/sessions/messages,
  PostgreSQL 17.11 и начальная миграция `accounts.0001_initial`.
  Предлагаемые специализации из документа используются как стартовый
  справочник; общий справочник навыков создаётся один, будущие требования
  проектов должны ссылаться на него. Навыки проектов и подбор не входят.
- Прямое поручение владельца включает рабочий профиль с хранением данных
  и пункт меню, поэтому необходимые модельные изменения и подключение
  навигации входят в эту работу. Применённые миграции не переписываются.
- Фото, портфолио, достижения, теги интересов и каталог студентов не входят
  в переданный MVP. Новые зависимости и изменения README/AGENTS не нужны.
- Функциональные тесты и ручная приёмка оставлены владельцу по его просьбе.
  Выполняются только служебные проверки, статический анализ и проверка БД.
