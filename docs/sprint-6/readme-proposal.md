## Блок 2 — заменить устаревший порядок первого запуска

Сохранить существующие команды создания `.env`, сборки и запуска БД. После них привести явный порядок:

```powershell
docker compose up -d --wait db
docker compose run --rm web python manage.py migrate --noinput
```

Для обычного демо Sprint 4–5:

```powershell
# Задайте локальный пароль в текущей сессии; не коммитьте его.
$env:SEED_DEMO_PASSWORD = '<ваш локальный демо-пароль>'
docker compose run --rm -e SEED_DEMO_PASSWORD web python manage.py seed_demo
docker compose up -d --wait web
```

Для изолированной приёмки каталога использовать пустую БД и набор P01–P10 по [review-demo.md](review-demo.md). Не смешивать его с Q01–Q13 или произвольными проектами: ожидаемые счётчики зависят от данных.

> Миграции и наполнение выполняются явно. `seed_demo` идемпотентен и не сбрасывает изменённые вручную заявки. Повторная сборка нужна при изменении исходников, поскольку Compose копирует код в образ. Обычная остановка — `docker compose stop` или `down` без `-v`; именованный volume сохраняет данные.

Удалить предупреждения «до появления кастомного пользователя не применять миграции» и «команда демо-данных пока не реализована»: они больше не соответствуют коду.

## Блок 3 — добавить «Каталог и OpenAPI»

> Каталог: `http://localhost:8000/projects/` при значении по умолчанию `WEB_PORT=8000`.
>
> Спецификация: [`docs/openapi.yaml`](../openapi.yaml), OpenAPI 3.1.0. Это файл репозитория, а не работающий endpoint. Она намеренно описывает HTML/HTMX, поскольку приложение не возвращает JSON каталога.
>
> Пример реального запроса после загрузки приёмочных данных:
>
> ```powershell
> curl.exe -i --get 'http://localhost:8000/projects/' `
>   --data-urlencode 'q=Python' `
>   --data-urlencode 'direction=development' `
>   --data-urlencode 'role=Backend' `
>   --data-urlencode 'open_only=true' `
>   --data-urlencode 'sort=newest'
> ```
>
> Ожидается `200 OK`, `Content-Type: text/html; charset=utf-8` и карточка `Python Lab`. Для фрагмента добавить `-H 'HX-Request: true'`: ответ начинается с `<section id="catalog-content">`. Это не JSON.
>
> Поиск не требует входа и CSRF. `open_only` принимает только `true`/`false`; отсутствие означает `true`. Повтор известного параметра или некорректное значение даёт HTML с ошибкой и HTTP 400. Небезопасный метод без CSRF может получить 403 раньше проверки разрешённых методов; после CSRF-проверки неподдерживаемый метод получает 405.

В PowerShell использовать `curl.exe`, чтобы не зависеть от алиасов Windows PowerShell. Для внешнего Swagger Editor учитывать Mixed Content/CORS: просмотр спецификации не означает доступность кнопки Try it out к локальному серверу.

> Тесты находятся в корневом `tests/` и запускаются на отдельной PostgreSQL, не SQLite. Для кириллического поиска проверить locale БД: на PostgreSQL 17.11 `C.UTF-8` проверки проходят; locale `C` не обеспечивает ожидаемое сравнение регистра.
>
> ```powershell
> docker compose run --rm web python -m pip check
> docker compose run --rm web python -m ruff check .

> docker compose run --rm web python manage.py makemigrations --check --dry-run

>
> Ruff и pytest должны быть доступны в выбранном окружении. Их отсутствие — неподтверждённая проверка, а не успех. Версии и включение инструментов в командный образ утверждает техлид; данное предложение не изменяет `requirements.txt`.
