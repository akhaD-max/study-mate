# Фильтры каталога проектов StudyMate

Подготовлено 05.11.2026, актуализировано 06.11.2026 по main `37ad0c9`. Для согласования с командой и проверки реализации.

Каталог должен помогать студенту найти подходящую роль в проекте. Для демо Sprint 6 используем существующий поиск, направление, одиночную роль, сортировку и переключатель открытого набора. Для полной версии предусматриваем множественный выбор направлений, ролей и сложности. Фильтр по навыкам и остальные расширения выделяем в следующий приоритет.

Этот документ описывает требования. Наличие требования здесь не означает, что функция уже реализована.

## 1 Объём демо Sprint 6

| Элемент | Что видит пользователь | Правило |
| --- | --- | --- |
| Поиск | Строка «Поиск проектов» и кнопка «Найти» | Подстрока в названии или описании. Без учёта регистра. Удаляются пробелы по краям. Поиск по кнопке или Enter. |
| Направление | «Все направления» и значения из справочника | Одно значение. Пустое значение означает все направления. |
| Роль в команде | «Любая роль» и названия из существующих ролей проектов | Одно название до 100 символов. Точное сравнение без учёта регистра. |
| Открытый набор | Переключатель «Только с открытым набором» | Включён по умолчанию. При включении учитывает статус проекта, открытость роли и наличие свободного места. |
| Сортировка | «Сначала новые», «Сначала старые», «Больше участников», «Меньше участников» | Использовать существующие четыре режима. При равенстве основного значения порядок должен быть устойчивым. |
| Сброс | Кнопка «Сбросить фильтры» | Возвращает начальные значения, включая включённый фильтр открытого набора. |

Пагинация — 12 проектов на страницу. Счётчик показывает все совпавшие проекты, а не только карточки текущей страницы.

### Что означает открытый набор

Проект попадает в выдачу при одновременном выполнении условий:

1. Статус проекта — `open`.
2. Существует роль этого проекта с `is_open=true`.
3. У этой же роли вместимость больше количества принятых участников.

Свободные места считаются по текущему членству. Заявки «На рассмотрении» места не занимают.

Не подходят: проект без ролей, проект только с полными или закрытыми ролями, проект со статусом `in_progress`, `completed` или `cancelled`. Одна открытая полная роль и другая закрытая свободная роль также не делают набор открытым.

При выключении фильтра разрешён просмотр проектов любых статусов с учётом остальных условий. Возможность откликнуться проверяется отдельно при подаче заявки. Наличие карточки в выдаче не резервирует место.

### Параметры существующего интерфейса

Используем `GET /projects/`. Обычный запрос возвращает HTML-страницу, HTMX — фрагмент `#catalog-content`. Отдельный JSON API для этой страницы не вводится.

| Параметр | Значения | По умолчанию |
| --- | --- | --- |
| `q` | Строка до 200 символов после удаления крайних пробелов | Пустая строка |
| `direction` | Один существующий `Category.slug` либо пустая строка | Все направления |
| `role` | Название роли до 100 символов; пустая строка означает любую роль | Любая роль |
| `open_only` | Только `true` или `false` | `true` |
| `sort` | `newest`, `oldest`, `members`, `fewer_members` | `newest` |
| `page` | Номер страницы | Первая страница |

Пример целевого запроса демо: `/projects/?q=Python&direction=development&role=Backend&open_only=true&sort=newest`.

По контракту от 05.11 непустой `q` ищется от одного символа. Пустая строка и пробелы отключают только текстовое условие. Внутренние пробелы сохраняются, вся строка ищется как одна подстрока. Поиск с опечатками, морфологией и автоматическим приравниванием «е» к «ё» не требуется.

Ошибочные значения `open_only`, длина `q` больше 200, длина `role` больше 100, неверный формат `direction` и повтор известного параметра дают HTTP 400. Неизвестный slug корректного формата или корректное, но отсутствующее название роли дают пустую выдачу с HTTP 200. Неизвестные параметры игнорируются. Неверная сортировка заменяется на `newest`.

Для `page` сохраняется существующее поведение: нечисловое или пустое значение — первая страница; ноль, отрицательное значение и номер больше последнего — последняя страница. Размер страницы не меняется.

### Состояние реализации по проведённому обзору

На коммите `37ad0c9` уже реализованы поиск, направление, одиночная роль, `open_only`, сортировки, пагинация и HTML/HTMX. Выбранная роль проверяется вместе со свободным местом через одну выборку; добавлены валидация и клиентские обработчики ошибок. Варианты ролей берутся из БД, совпадения регистра объединяются. Синонимы вроде «Backend» и «Backend-разработчик» остаются разными значениями. Это сверка исходников, а не новый запуск приложения или подтверждение прохождения кейсов. Параметр `role` добавлен реализацией сверх таблицы старого общего контракта и требует синхронизации его владельцем.

## 2 Фильтры полной версии

### Основной набор

| Фильтр | Тип выбора | Значения и назначение | Начальное состояние |
| --- | --- | --- | --- |
| Поиск | Текст | Название или описание проекта | Пусто |
| Направления | Множественный | Разработка, Дизайн, Наука и согласованные расширения справочника | Все |
| Требуемые роли | Множественный | Роли, на которые команда ищет участников | Все |
| Сложность | Множественный | Начальный, Средний, Продвинутый | Все |
| Только с открытым набором | Переключатель | Проекты с доступной открытой ролью | Включён |
| Сортировка | Одиночный | Существующие четыре режима | Сначала новые |

Показывать действующими можно только те фильтры, для которых есть данные и реализация. Множественный выбор ролей и сложность остаются требованиями полной версии; в текущем демо роль выбирается одна.

### Направления проектов

Предлагается одно основное направление у проекта. Множественный выбор направлений относится к фильтру каталога, а не к обязательному присвоению нескольких направлений каждой карточке.

| Направление | Примеры проектов | Состояние справочника |
| --- | --- | --- |
| Разработка | Бот расписания, каталог университетских мероприятий | Уже есть `development` |
| Дизайн | Навигация по кампусу, дизайн-система студенческих сервисов | Уже есть `design` |
| Наука | Исследование микроклимата, исследование учебных привычек | Уже есть `science` |
| Аналитика данных | Анализ онлайн-курсов, анализ загрузки аудиторий | Предлагается |
| Игры и интерактивные проекты | Игра по алгоритмам, виртуальная экскурсия | Предлагается |
| Инженерия и устройства | Датчик качества воздуха, автоматический полив | Предлагается |
| Медиа и коммуникации | Научный подкаст, медиапроект конференции | Предлагается |
| Социальные и организационные проекты | Обмен учебниками, волонтёрское мероприятие | Предлагается |

Темы «Образование», «Экология», «Культура» лучше хранить отдельными тематическими тегами: они могут относиться к любому направлению. Команда должна согласовать это разделение, поскольку в действующем US-04 образование приведено среди примеров направлений. Существующие значения не переименовываются автоматически.

### Справочник ролей

Начальный список для согласования: Backend-разработчик, Frontend-разработчик, UI/UX-дизайнер, QA-инженер, Аналитик данных, Руководитель проекта, Исследователь, Разработчик игр, Разработчик встраиваемых систем, Редактор или специалист по коммуникациям.

Для полной версии названия ролей в фильтре предлагается брать из общего справочника. В текущем демо список собирается из существующих `ProjectRole` и объединяет только различия регистра. Иначе варианты «Backend», «Бэкендер» и «Backend-разработчик» окажутся разными условиями. Свободный текст описания роли можно сохранить отдельно. Привязку существующих записей и изменения схемы согласовать с Денисом.

### Значение уровней сложности

| Уровень | Ориентир для студента |
| --- | --- |
| Начальный | Есть небольшие понятные задачи, достаточно базовых знаний, предусмотрено сопровождение новичка. |
| Средний | Нужно самостоятельно выполнять задачи и иметь опыт учебной работы с нужными инструментами. |
| Продвинутый | Требуется уверенное владение инструментами и самостоятельное решение сложных задач. |

Уровень задаёт руководитель для проекта. Это ориентир, который не заменяет описание требований конкретной роли. Правила назначения уровня нужно согласовать, чтобы команды использовали шкалу одинаково.

## 3 Правила совместной работы фильтров

**Между группами применяется AND.** Например, направления «Разработка» или «Дизайн», роль «UI/UX-дизайнер» и сложность «Начальный» дадут начальные проекты этих направлений, которым нужен дизайнер.

**Внутри группы применяется OR.** Две выбранные роли означают, что достаточно одной из них. Пустая группа не ограничивает выдачу.

**При выборе роли и открытого набора проверяется одна и та же роль.** Проект с полной Backend-ролью и свободной Frontend-ролью не подходит под «Backend-разработчик» вместе с «Только с открытым набором». Если выбрано несколько ролей, достаточно одной подходящей открытой роли со свободным местом.

Один проект показывается один раз, даже если совпало несколько ролей. Сначала выполняются все условия, затем сортировка и пагинация. Число карточек и общий счётчик должны относиться к одной и той же выборке.

После изменения поиска, фильтра или сортировки открывается первая страница. При переходе между страницами сохраняются все условия. Обновление страницы, прямой URL и Back/Forward восстанавливают выбранные значения.

Сброс возвращает: пустой поиск, все направления, все роли (в демо — «Любая роль»), все уровни, открытый набор включён, сначала новые, первая страница. Формулировку US-04 о «полном списке» при сбросе следует уточнить: в предлагаемом варианте это начальная выдача открытого набора.

## 4 Поиск в полной версии и демо

| Правило | Демо по контракту от 05.11 | Полная версия по действующему US-04 |
| --- | --- | --- |
| Запуск | Кнопка «Найти» или Enter | Автоматически от трёх символов |
| Один или два символа | Выполняется текстовый поиск | Подсказка «Введите минимум 3 символа для поиска» |
| Пустая строка | Текстовое условие отключено | Текстовое условие отключено |
| Область поиска | Название или описание | Название или описание |
| Регистр | Не учитывается | Не учитывается |

Для полной версии предлагается задержка 350 мс после окончания ввода. При 1–2 символах сохраняется предыдущая выдача с явной подсказкой, новый текстовый поиск не выполняется. После очистки строки выдача обновляется по остальным фильтрам. Ответ на более ранний запрос не должен перезаписывать результат более позднего.

Задержка и точное поведение короткой строки — уточнения для согласования. Различие с демо нельзя устранять молча: единое поведение нужно принять отдельным решением и затем синхронно обновить ЮС, контракт и кейсы.

## 5 Состояния интерфейса

| Состояние | Ожидаемое отображение |
| --- | --- |
| Загрузка | Индикатор «Обновляем каталог…». Выбранные условия видны. |
| Есть совпадения | Карточки, общее количество, пагинация при необходимости. |
| Нет совпадений | «Проекты с такими параметрами не найдены», предложение изменить условия и кнопка сброса. |
| Ошибочные параметры | Ошибка рядом с полем, сохранённый ввод. Для демо по контракту — HTTP 400. |
| Ошибка сервера или сети | «Не удалось загрузить каталог. Повторите попытку», кнопка повтора. Предыдущие карточки сохраняются с указанием, что выдачу не удалось обновить. |

Пустой ответ и сбой загрузки различаются. При повторе отправляются те же условия. Поиск и фильтры должны быть доступны с клавиатуры и иметь текстовые подписи.

## 6 Следующий приоритет полной версии

| Расширение | Что требуется согласовать до разработки |
| --- | --- |
| Навыки | Единый справочник, требования на уровне проекта или роли. Предложение: требования роли; несколько навыков внутри фильтра означают «хотя бы один». |
| Формат участия | Удалённо, очно, гибридно; необходимость города для очного формата. |
| Нагрузка | Часы в неделю и понятные диапазоны, возможность оставить значение неизвестным. |
| Срок набора | Отдельная дата окончания откликов, не дата завершения проекта. |
| Тематические теги | Единый набор тем, правила назначения и множественного выбора. |

Если навыки вводятся на уровне роли, роль, её навыки и свободное место должны совпадать в одной записи. Фильтр «Все выбранные навыки» и сортировку по проценту совпадения следует описывать отдельными требованиями.

## 7 Передача команде

Для демо следующий шаг — выполнить приёмочные кейсы, включая отказ сети, таймаут и HTTP 500, а также синхронизировать описание `role` в общем контракте. Наличие обработчиков в коде не подтверждает их проверку в браузере. Для полной версии нужно утвердить справочники направлений и ролей, сложность и поведение автопоиска. Модели и миграции ведёт Денис. HTTP-имена новых множественных фильтров полной версии здесь не утверждаются.
