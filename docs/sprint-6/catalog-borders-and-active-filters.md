# Каталог: окаймовка блоков и выбранные фильтры под поиском

Дата: 20.11.2026. Ветка: `arena/60a6dca6-study-mate`, база — `a05ed61` (`main`).

## Задача и критерии приёмки

Цель — доработать существующую страницу каталога по образцу присланного макета, не переписывая её:

1. Каждый проект в списке каталога получает явную окаймовку.
2. Под строкой поиска появляется отображение текущих выбранных фильтров, тоже с окаймовкой.
3. Блоки с информационными сообщениями (пустая выдача, ошибка запроса, сбой загрузки, ошибки полей) тоже получают окаймовку.

Ограничения: сохранить текущую структуру страницы, серверную фильтрацию, HTMX-фрагмент, разделение 200/400, отсутствие JS-зависимостей для базового сценария. Модели, миграции, зависимости и базовый шаблон не меняются.

## Реализация

### Окаймовка карточек проектов

`static/css/catalog.css`: для `.catalog-card` на странице поиска рамка усилена с `1px solid #e7e8ef` до `2px solid #161c2e` (переменная `--catalog-outline`), радиус — `16px`. Ховер сохраняет ту же рамку и даёт мягкую тень, поэтому «прыжка» границы при наведении нет. Правила действуют только внутри `.catalog-search-page`, чтобы не затронуть карточку проекта и формы.

### Выбранные фильтры под строкой поиска

`projects/views.py`, функция `catalog`:

- в контекст добавлены `active_filters` и `reset_url`;
- каждый чип содержит `key`, `label`, `value`, `action` (текст `aria-label`) и `remove_url` — ссылку на каталог без этого одного условия;
- `catalog_href` собирает URL без пустых значений и без `page`: изменение условий, как и раньше, начинает выдачу с первой страницы;
- чипы строятся по тем же нормализованным значениям, что и форма: направление показывается названием из `Category` (для неизвестного слага — самим слагом), сортировка — человекочитаемой подписью;
- состояние набора показывается всегда: «Набор: Открыт» — фильтр по умолчанию, чип переключает его на «Все проекты» и обратно, а не просто снимает;
- «Сбросить всё» показывается, только когда есть что сбрасывать (`has_filters` или сортировка не по умолчанию).

`projects/templates/projects/partials/catalog_content.html`: блок `.catalog-active-filters` размещён внутри `.catalog-search-panel` сразу под строкой поиска и ошибкой поля `q`. Каждый чип — ссылка с `hx-get`/`hx-target="#catalog-content"`/`hx-swap="outerHTML"`/`hx-push-url`, то есть работает без JavaScript как обычная ссылка и без перезагрузки страницы при HTMX. Подписи доступны скринридеру: `role="group"` с `aria-label="Выбранные фильтры"`, у чипа — `aria-label` с описанием действия, крестик помечен `aria-hidden`.

Так как блок находится внутри `#catalog-content`, он обновляется вместе с выдачей при HTMX-запросе, при восстановлении истории и после сброса.

### Окаймовка информационных блоков

- `.catalog-empty` (пустая выдача и «ничего не найдено») — рамка `2px` тёмного цвета, радиус `16px`;
- вариант `.catalog-empty-error` (ошибка валидации поиска) — та же рамка, но красная, с розовым фоном и красным заголовком;
- `.catalog-request-error` (сбой сети/сервера, блок `#catalog-request-error` в `catalog.html`) — красная рамка `2px`, у кнопки «Повторить попытку» появилась рамка и состояние наведения;
- `.catalog-field-error` — сообщение об ошибке конкретного поля теперь в рамке, поле с `aria-invalid="true"` получает красную границу;
- индикатор «Обновляем каталог…» в состоянии `htmx-request` — в рамке и с подложкой, чтобы его не терять на фоне списка.

- тесты на PostgreSQL и `manage.py migrate --check` — сервер БД в песочнице отсутствует (`Connection refused` на 127.0.0.1:5432), SQLite не подменялся;
