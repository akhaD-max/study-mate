# Подключить создание проектов, заявки и команду к основному приложению

Ветка: `feat/008-project-integration` → `main`. Ответственный: Данила.

В обычном Docker-запуске формы и сервисы были доступны только в демоконфигурации. Подключены `applications` и основные URL; каталог использует один обработчик, старое имя URL сохранено.

Добавлены GET/POST создания проекта с ролями, карточка и GET формы отклика. Обычный POST перенаправляет после успеха и сохраняет ввод при ошибках. HTMX заменяет `#application-form` через `outerHTML`, показывая отправленную заявку или ошибки. Автор и заявитель берутся из сессии; включены вход и CSRF.

Добавлены страницы моих проектов/заявок, входящие заявки руководителя, сервисы принятия/отклонения/отзыва и выхода из команды. Принятие атомарно создаёт членство и обновляет статус с повторной проверкой места под блокировками PostgreSQL. Новые страницы оформлены в существующем стиле каталога. Моделей, миграций и новых зависимостей нет.

Интеграционные тесты переведены на `config.settings` и основные URL. Добавлены HTTP-проверки обычных/HTMX-форм, доступа, CSRF, ошибок и полного пути участника; проверяется гонка двух приёмов на последнее место через отдельные соединения.

Подробный отчёт, команды и результаты: `docs/008-project-integration-report.md`. Публикацию ветки и PR выполняет Данила; merge требует ревью.

Проверено: **109 pytest-тестов** на основных настройках и PostgreSQL 17.11, локальный Ruff, pip check, Django check, обе проверки миграций, git diff --check. Docker-контейнеры healthy; браузером пройден путь регистрации → создания → HTMX-отклика → принятия → участия → выхода с освобождением места.

В Docker Ruff требуется временный каталог кэша и исключение EXE002 из-за исполняемых битов файлов при COPY из Windows; остальные проверки чистые. Подробности и точная команда есть в отчёте. Модели, миграции, зависимости, README и Docker-конфигурация не менялись.
