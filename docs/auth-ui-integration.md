# Интеграция интерфейса входа и регистрации

## Задача и границы

- Цель: перенести предоставленные макеты в Django templates и существующий HTMX 2.0.11, без Tailwind и внешних CDN.
- Критерии: email/пароль на обеих страницах, без SSO и дополнительных полей регистрации; Inter; адаптивная двухколоночная композиция; серверные ошибки, CSRF, обычная отправка и HTMX.
- Ветка: `arena/56ec8d03-study-mate`.
- Исполнитель: агент Arena по поручению владельца задачи. Ответственный за ревью/публикацию PR — владелец задачи.
- Зависимости: существующие Django auth, модель User, URL accounts и локальный HTMX. Новых Python-зависимостей и миграций нет.

## Изменения

- `templates/base.html`: добавлены расширяемые блоки `extra_head` и `layout`, существующий макет каталога остаётся по умолчанию.
- `accounts/templates/accounts/`: общий макет авторизации, отдельные страницы и фрагменты форм. В гостевой шапке только работающая ссылка на каталог. Ссылка восстановления пароля не добавлена: соответствующего маршрута пока нет.
- `static/css/auth.css`: изолированные адаптивные стили по макетам; `static/css/app.css`: локальный Inter в общей типографике.
- `static/fonts/`: Inter variable (latin/cyrillic), лицензия SIL OFL. Источник: npm `@fontsource-variable/inter`, файлы `files/inter-{latin,cyrillic}-wght-normal.woff2`; лицензия из `@fontsource/inter`. Во время работы приложения внешние запросы для шрифта не нужны.
- `static/js/auth.js`: делегированное переключение видимости пароля, фокус после HTMX-обновления, сообщение об ошибке запроса. Пароль не вставляется в HTML после ошибки валидации.
- `accounts/forms.py`: email-виджеты, autocomplete и подсказки. Имена `username`/`password` для входа сохранены ради контракта Django.
- `accounts/views.py`: восстановлены отсутствовавшие импорты, HTMX получает фрагмент при ошибках и `HX-Redirect` после успешной авторизации; обычные POST сохраняют стандартные редиректы и безопасный `next` из LoginView.
- `tests/accounts/test_auth_ui.py`: проверки разметки и ошибок форм без БД, а также тесты успешной регистрации/входа с БД.

## Проверки

Окружение sandbox: Python 3.11.2, Django 5.2.17; Python 3.13.16 проекта здесь недоступен. Зависимости установлены только в локальную `.venv`, requirements.txt не изменён.

Успешно:

- `python manage.py check`.
- `python manage.py test tests.accounts.test_auth_ui.AuthPageTests`: 3 теста, включая обе страницы, обычные и HTMX-ошибки.
- `python -m ruff check accounts/forms.py accounts/views.py tests/accounts/test_auth_ui.py`.
- Ruff format изменённых Python-файлов.
- `python -m pip check`.
- `git diff --check`.
- `makemigrations --check --dry-run`: изменений моделей не обнаружено, но проверка истории миграций предупредила о недоступной БД.

Блокеры/непроверенное:

- `migrate --check` и интеграционные тесты успешной авторизации требуют PostgreSQL; сервер на 127.0.0.1:5432 в sandbox недоступен. SQLite не использовался.
- `python -m pytest tests`: существующий запуск не инициализирует Django, остановка на сборе тестов (settings are not configured). Настройка общего тестового окружения не менялась.
- Общий `python -m ruff check .`: четыре прежних замечания в `accounts/middleware.py` и `main/views.py`; посторонние файлы не изменялись.
- Визуальная проверка в реальном браузере и полный набор тестов на PostgreSQL остаются перед интеграцией.
