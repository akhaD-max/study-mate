# Экран «Входящие заявки» по макету и общий подвал

Дата: 20.11.2026. Ветка: `arena/60a6dca6-study-mate`, база — `a05ed61` (`main`).

## Задача

1. Обновить экран заявок руководителя (`applications:incoming`) по предоставленному макету.
2. На странице профиля поставить такой же подвал, как на остальных страницах.

Блок совместимости навыков, добавленный по `docs/contracts.md` в предыдущей задаче, сохранён внутри новой карточки заявки.

## Реализация

### `applications/views.py`

Добавлена `incoming_context(request, project_id, errors=None)` — один источник контекста для обычного показа и повторного рендера после ошибки принятия/отказа:

- `applications` — заявки с уже посчитанным `skill_match` и фильтром по статусу;
- `counts` — сквозные счётчики `all/pending/accepted/rejected` по всем заявкам проекта, не зависящие от выбранного таба;
- `active_status` и `filter_active` — состояние табов;
- неизвестное значение `?status=` показывает все заявки, чтобы сохранённая ссылка не давала пустой экран.

Порядок выдачи не менялся: контракт Sprint 8 оставляет «новые сначала», сортировка по проценту относится к общему US-10.

### `applications/templates/applications/incoming.html`

Разметка перенесена с макета:

- контекст проекта — ссылка-назад на карточку и плашка статуса проекта;
- синий hero с сеткой, заголовком «Входящие заявки», подзаголовком с названием проекта и фирменной «искрой»;
- карточка-дашборд с табами «Все · 3 / На рассмотрении · 1 / Приняты · 1 / Отклонены · 1». В макете табы — кнопки с JS-переключением классов; здесь они сделаны ссылками `?status=…`, потому что данные приходят с сервера: фильтр работает без JavaScript и переживает перезагрузку, а активный таб помечен `aria-current="page"`;
- карточка заявки: имя со ссылкой на профиль, плашка статуса, роль и дата, свёрнутое сопроводительное письмо в плашке;
- блок совместимости по контракту — процент, «Нет данных», пустой профиль, подпись для рассмотренных заявок, группы «Совпадают» / «Не хватает» / «Дополнительные навыки»;
- правая колонка по статусу: для заявки на рассмотрении — подпись «Ожидает вашего решения» и кнопки «Принять» / «Отклонить» (реальные POST-формы с CSRF); для принятой — «В команде» и пояснение; для отклонённой — «Архив заявок» и ссылка «Профиль кандидата»;
- пустые состояния: «Пока нет заявок» и «Здесь пусто» с возвратом к `?status=all`.

Обработчик табов из макета на JavaScript не добавлялся: он подменял только подсветку кнопок и не фильтровал список, поэтому на серверных данных дал бы неверное поведение.

Стили подключены через `{{ block.super }}` в `extra_head`, чтобы сохранить `catalog.css`, `workflow.css` и `pages.css` родительского `workflow.html`.

### `static/css/incoming.css`

Отдельный файл в языке макета: карточка-дашборд с рамкой и радиусом 28px, hero с blueprint-сеткой, табы-«пилюли» с лаймовым активным состоянием, двухколоночные карточки заявок с hover-тенью, плашки статусов, блок совместимости, пустые состояния, адаптив на 1000px и 640px, поддержка `prefers-reduced-motion`. Классы с префиксом `in-` изолированы от остальных страниц.

### Общий подвал

Подвал вынесен в `templates/partials/site_footer.html` и подключён в четырёх базовых шаблонах: каталог (`projects/catalog.html`), сценарии (`workflow.html` — мои заявки, мои проекты, заявка, карточка проекта, входящие), профиль (`accounts/profile_base.html`), авторизация (`accounts/base_auth.html`).

- На профиле прежний `.profile-footer` («StudyMate · Профиль участника» / «Найти свою команду») заменён общим подвалом с `studymate / сделаем вместе` и «Учебный проект · Ростелеком».
- В сценариях подвал раньше отличался подписью «Найди свою команду» — теперь он совпадает с каталогом.
- Стили подвала вынесены из `catalog.css` в отдельный `static/css/footer.css`, который подключается в `templates/base.html`; профиль (он не наследует `base.html`) подключает файл сам.

### Исправление сломанного подвала на входе и регистрации

После унификации подвал на страницах авторизации рендерился без оформления — белой полосой с текстом. Причина: класс `catalog-footer` был описан только в `catalog.css`, а `accounts/base_auth.html` подключает исключительно `auth.css`. Правила перенесены в `footer.css` (фон `#141416`, светлый текст, отступы, мобильная раскладка), поэтому подвал одинаково чёрный на всех страницах. Прижимание к низу в колоночных раскладках (`catalog-shell`, `auth-shell`, `profile-page`) задаётся через `margin-top: auto`.

Старые, ставшие неиспользуемыми правила удалены: `.auth-footer*` из `auth.css`, `.profile-footer` из `profile.css`, дубль `.catalog-footer` из `catalog.css`.

## Списки навыков в блоке совместимости

По умолчанию карточка показывает только процент и количество
(«75% · совпало 3 из 4 навыков»). Навыки раскрываются в два уровня:

1. «Подробности» (`details.in-skill-details`) — совпавшие и недостающие
   навыки, это основание для решения по заявке;
2. «Дополнительные навыки» (`details.in-skill-extra`) — вторая ступень,
   доступна уже внутри раскрытых «Подробностей».

Обе ступени — нативные `<details>/<summary>`, работают без JS, состояние
по умолчанию — свёрнуто. В заголовке группы стоит число навыков, состояние
показывает CSS-индикатор `.in-skill-toggle`.

Важно: Django не поддерживает многострочные `{# … #}` — такой комментарий
попадает в HTML как текст. Для пояснений в шаблоне используется
`{% comment %} … {% endcomment %}`.
