# Интеграция макета профиля

Дата: 14.11.2026. Продолжение задачи 025 в `feat/025-user_profile`,
поверх `500e8f8`. Ответственный за приёмку и публикацию PR — владелец
задачи; исполнитель — Codex. Постановка до изменений дополнена в
`docs/025-user-profile-task.md`.

## Результат

Полностью прочитаны оба HTML-файла из Downloads (`message.txt` — профиль,
`message (2).txt` — редактор), использованы оба приложенных скриншота.
Структура макета перенесена в Django templates: синий баннер с сеткой,
аватар с инициалами, белые карточки, сиреневые заголовки, теги навыков,
список проектов со статусами, форма с полями в две колонки, кнопки
сохранения и отмены. Добавлены перестроения для узких экранов.

Стили и шрифт Inter подключены локально, общая навигация и меню
пользователя переиспользованы из проекта. Tailwind и CDN из исходных
макетов не добавлены. Все отображаемые в приложении сведения берутся
из существующей БД; примеры Александры и четырёх проектов использовались
только в локальном визуальном предпросмотре вне отслеживаемых файлов.

Форма сохраняет прежний POST-контракт, CSRF, ошибки и введённые значения.
Продолжают действовать валидация, транзакционное сохранение и права
владельца. Имя и фамилия остаются одним необязательным полем, курс 1–6
и желаемая роль выбираются из списков, специальность обязательна.
Сохранён счётчик описания и предупреждение об уходе без сохранения.

В редактор добавлен раскрываемый выбор навыков с поиском по справочнику.
Выбранные навыки отображаются тегами; крестик снимает соответствующий
checkbox. При попытке выбрать шестнадцатый навык показывается сообщение.
Серверная проверка 1–15 уникальных UUID остаётся обязательной и работает
независимо от JavaScript. Без JS выбор работает через обычный HTML details
и checkboxes, сохранение — обычным POST.

Правая колонка теперь содержит реальные проекты, где студент — автор
или действующий участник. Авторство и членство одного проекта не дают
дублей. Роль участника берётся из ProjectMember/ProjectRole, роль автора
подписывается «Автор проекта». Фильтры «Все», «В работе», «Завершённые»
и счётчики работают с PostgreSQL; пагинация — по 6 проектов.
Параметры страницы: `project_tab=all|in_progress|completed`, `page`.
Это фильтр внутри существующей карточки профиля, отдельный endpoint
US-03 и его дополнительные фильтры в эту работу не добавлялись.

При просмотре чужой карточки выводятся только проекты `in_progress`
и `completed`, как предусмотрено US-03; заявки и их счётчик доступны
только владельцу. Кнопки и ссылки ведут на действующие страницы.

Город, Telegram, портфолио и флаг готовности из макета не входят в
существующую модель и согласованный MVP. Их не выводим как неработающие
поля. Загрузка фото по прежнему поручению не добавлялась, используется
заглушка с инициалами. Фальшивые ссылки помощи и контактов из макета
не переносились.

| `docs/025-user-profile-report.md` | Добавлена ссылка на актуальный отчёт оформления; первоначальный отчёт сохранён как история первого этапа |
| `docs/025-user-profile-design.md` | Этот отчёт |

этапе нет. Файлы предпросмотра находятся только в игнорируемой `.local/`.
