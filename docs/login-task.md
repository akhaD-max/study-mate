# Задача 007: вход по email и сессии Django

- Ответственный разработчик: Даня. Восстановление ветки и проверка: Codex
  по прямому поручению владельца задачи.
- Ветка: `feat/007-autorization`, база — актуальная `origin/main` с регистрацией
  (`72d9e8b`). Зависимость: `accounts.User` и уже подготовленные миграции.
- Цель: сохранить написанный разработчиком вход после конфликта при переносе
  изменений в GitHub Desktop и опубликовать отдельный PR в `main`.
- Файлы: `accounts/views.py`, `accounts/urls.py`,
  `accounts/templates/accounts/login.html`, `tests/accounts/test_login.py`.
- Контракт: GET/POST `/accounts/login/`, namespace `accounts:login`,
  `LoginPageView`, стандартная `AuthenticationForm`; поле `username` принимает
  email согласно `User.USERNAME_FIELD`. HTML-форма с CSRF, без HTMX.
- Приёмка: вход по email без учёта регистра, сохранение сессии, одинаковая
  ошибка для неверного пароля и неизвестного email, отказ неактивному
  пользователю, переход на главную или безопасный внутренний `next`.
- Модели, миграции и зависимости не изменяются.

## Восстановление Git

Ветка была создана от устаревшей локальной `main` (`983d0de`), которая
отслеживала локальное окружение и не содержала `.gitignore`. Перенос изменений
через Bring changes привёл к конфликту в `views.py` и отображению `.pyc`.

Рабочие файлы и три стадии конфликта сохранены в локальной `.local/recovery/`.
Исходная история сохранена в локальных ветках `recovery/`; они не публикуются.
Ветка задачи восстановлена от `origin/main`, поверх перенесены три файла входа.
Локальная `main` синхронизирована с `origin/main`, старая сохранена отдельно.
Существующее игнорирование исключает кэши, `.env` и окружение Python из Git.
Локальное окружение и данные PostgreSQL сохранены.
