# Подготовить окружение, Django-каркас и Docker Compose

Репозиторий содержал только документацию и зависимости. Добавлены Django-проект
`config` без доменных приложений, корневая страница, базовый шаблон и локальный
HTMX 2.0.11. Python 3.13.16 и PostgreSQL 17.11 закреплены по digest; Compose
собирает оба образа и запускает их с healthcheck и локальными портами.

Секреты передаются через окружение. Генератор `.env` создаёт случайные значения
без перезаписи существующего файла. Локальное окружение и секреты исключены из
Git и Docker. В README после стека добавлен утверждённый гайд клонирования
и запуска; удалены только разделы «Подготовка окружения сейчас», «Вариант A»,
«Вариант B», «Остановка и типовые проблемы». Остальные разделы сохранены.
requirements.txt и AGENTS.md не изменены; подробная инструкция и отчёт
находятся в docs/.

Ветка: `feature/django-docker-bootstrap`, целевая ветка: `main`.
Слияние выполняет владелец задачи вручную после ревью.

Проверено: установка исходных требований в Windows `.venv` и Linux-образе,
pip check, Ruff 0.17.1, Django check, makemigrations --check --dry-run,
полная сборка Compose, healthy обоих сервисов, HTTP 200 страницы и HTMX,
подключение PostgreSQL 17.11. В отдельной пустой проверочной БД успешно
применены 18 стандартных миграций и выполнен migrate --check.

Собственных миграций нет. Рабочая база оставлена без таблиц до утверждения
модели пользователя. Pytest-тестов пока нет: добавлен только инфраструктурный
каркас, сценарии проверены вручную. Версии инструментов разработки в командных
зависимостях и dev-образе должен закрепить техлид.

Следующий шаг владельца задачи: ревью и ручное слияние PR; следующий шаг
техлида: согласовать модель пользователя и версии инструментов разработки.
