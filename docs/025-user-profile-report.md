## Реализованное поведение

- Свой профиль: `/profile/` перенаправляет на карточку вошедшего студента.
- Чужой профиль: `/profile/<UUID>/`, только после входа.
- Редактор: `/profile/edit/`, всегда изменяет пользователя из сессии.
- Совместимые URL внутри accounts: `/accounts/profile/`,
  `/accounts/profile/edit/`, `/accounts/profile/<UUID>/`.
- После новой регистрации открывается редактор; обычный вход сохраняет
  прежний маршрут и поддержку безопасного `next`.
- Успешное сохранение перенаправляет на карточку и показывает сообщение
  «Профиль успешно обновлён».
- При ошибке форма остаётся заполненной, ни поля, ни навыки не сохраняются.
- Чужая карточка не содержит кнопки редактирования. POST в любую карточку
  отклоняется с 405. Маршрута редактирования по чужому UUID нет (404),
  переданный в POST произвольный ID не участвует в выборе владельца.
- Гость направляется на вход с `next`; несуществующий или неактивный
  пользователь даёт 404 после проверки входа.
- Email, пароль, заявки, статусы и письма в карточку не выводятся.
  `get_full_name()` и `get_short_name()` теперь возвращают «Студент»
  при отсутствии имени, поэтому email больше не подставляется вместо имени
  в существующие карточки, состав команды и меню.
- Желаемая роль меняется и очищается, не затрагивает заявки и права.
- Аватар — только текстовая заглушка. Поля загрузки и обработки файлов нет.
- Новые страницы используют обычную HTML-разметку без CSS. Небольшой
  JavaScript нужен только для счётчика и защиты несохранённого ввода.

## Поля и проверки

| Поле | Реализация |
| --- | --- |
| Имя и фамилия | Необязательно, до 150 символов, без ограничений алфавита и числа слов |
| Вуз | Обязательно в редакторе, до 200 символов, пробелы по краям удаляются, одни пробелы не принимаются |
| Специальность | Те же правила, до 200 символов |
| Курс | Обязательный выбор целого 1–6, начального выбранного курса нет; диапазон дополнительно закреплён в БД |
| Навыки | 1–15 доступных UUID из общего справочника; дубли, включая разные записи одного UUID, отклоняются; hard и soft считаются вместе |
| Желаемая роль | Необязательный UUID доступной специализации, пустое значение сохраняется как NULL |
| О себе | Необязательно, до 1000 символов, сервер отклоняет превышение; HTML экранируется, переносы строк отображаются |

Обязательность контролирует форма. В БД основные поля допускают отсутствие
значения, чтобы регистрация только с email и паролем и старые аккаунты
продолжали работать. Для незаполненного профиля предусмотрено сообщение
«Пользователь пока не заполнил профиль».

Сохранение выполняется в транзакции с блокировкой записи пользователя.
Используется явный список полей: пользовательский POST не может изменить
email, пароль, UUID, staff/superuser или другие служебные значения.

Отмена и переходы по ссылкам при изменённой форме открывают HTML dialog
с действиями «Остаться» и «Выйти без сохранения». При перезагрузке или
закрытии страницы используется стандартное предупреждение браузера;
его текст браузер выбирает самостоятельно. Без JavaScript просмотр,
валидация и сохранение работают; счётчик не обновляется во время ввода
и предупреждение об уходе не появляется.

## PostgreSQL и запуск

До изменений проверено реальное соединение Django: backend `postgresql`,
БД `studymate`, PostgreSQL 17.11. Неприменённых миграций не было.
До и после миграций количество существующих записей одинаковое:
5 пользователей, 1 проект, 0 участников и 1 заявка.

`docker compose build web` успешно собрал образ с текущими исходниками.
`docker compose run --rm --no-deps web python manage.py migrate --plan`
показал только две новые миграции accounts.
`docker compose run --rm --no-deps web python manage.py migrate` применил
`0002_profile_fields` и `0003_profile_catalogs`, обе с результатом OK.
`docker compose up -d --wait web` пересоздал web с новым образом.
Состояние db и web — healthy. Именованный volume сохранён.

Профиль доступен по `http://localhost:8001/profile/`, редактор —
`http://localhost:8001/profile/edit/`. Вход обязателен.

ветку и PR в main с подготовленным описанием. Денису: ревью схемы,
