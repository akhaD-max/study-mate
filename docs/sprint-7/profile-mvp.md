# MVP профиля студента StudyMate

## 1. Цель

Студент может заполнить сведения о себе, указать навыки и желаемую роль. Другие зарегистрированные студенты могут открыть его профиль и понять, какие задачи ему интересны и какие навыки он заявляет.

Автор проекта использует эту же карточку для знакомства с кандидатом. Дополнительных прав на редактирование чужого профиля у него нет.

В MVP реализуем:

- Просмотр собственного и чужого профиля.
- Редактирование собственного профиля.
- Выбор навыков и желаемой роли из справочников.
- Сохранение данных в PostgreSQL.
- Проверку заполнения, ошибок и прав доступа.

Портфолио, достижения и загрузка фотографии пока не входят. Вместо фотографии используется нейтральная заглушка.

## 2. Поля профиля

| Поле | Обязательность | Настройка |
|---|---|---|
| Имя и фамилия | Обязательно при сохранении профиля | Текст, предлагаемый максимум 150 символов |
| Вуз | Обязательно | Текст, предлагаемый максимум 200 символов |
| Специальность | Обязательно | Текст, предлагаемый максимум 200 символов |
| Курс | Обязательно | Выбор одного значения от 1 до 6 |
| Навыки | Обязательно | От 1 до 15 уникальных значений из общего справочника |
| Желаемая роль | Необязательно | Для MVP — выбор одной специализации из справочника |
| О себе | Необязательно | Текст до 1000 символов |

Обязательность вуза, специальности, курса и навыков, а также ограничения курса, навыков и описания сохраняются из US-02. По уточнению владельца задачи имя и фамилия также обязательны при сохранении профиля; соответствующее изменение в US-02 вносит владелец задачи. Максимальная длина имени, вуза и специальности — предложения для согласования.

При регистрации по-прежнему нужны только email и пароль. Обязательность имени и фамилии проверяется при сохранении профиля: сразу после регистрации или у ранее созданного аккаунта профиль может быть ещё не заполнен.

## 3. Желаемая роль

Поле показывает, какую работу студент хочет выполнять в команде. Оно помогает другим участникам понять его предпочтение.

Желаемая роль не подтверждает квалификацию, не назначает человека в команду и не предоставляет права управления проектом.

Предлагаемый справочник специализаций:

| Роль | Какие задачи предполагает |
|---|---|
| Backend-разработчик | Серверная логика, работа с БД, обработка запросов |
| Frontend-разработчик | Интерфейс сайта и взаимодействие пользователя с ним |
| Fullstack-разработчик | Задачи серверной и клиентской частей |
| Мобильный разработчик | Приложения для мобильных устройств |
| Разработчик игр | Игровая логика и механики |
| Тестировщик / QA | Проверка поведения системы, поиск и описание ошибок |
| Системный аналитик | Требования к системе, сценарии, данные и взаимодействие компонентов |
| Бизнес-аналитик | Потребности пользователей, процессы и бизнес-требования |
| Аналитик данных | Анализ данных, показатели, отчёты и визуализация |
| ML-разработчик | Подготовка и применение моделей машинного обучения |
| UI/UX-дизайнер | Пользовательские сценарии, структура экранов и интерфейс |
| Графический дизайнер | Иллюстрации, оформление и графические материалы |
| 3D-дизайнер | Трёхмерные модели и визуальные материалы |
| DevOps-инженер | Окружение, сборка, развёртывание и эксплуатация |
| Специалист по информационной безопасности | Анализ защищённости и требований безопасности |
| Маркетолог | Исследование аудитории и продвижение результата проекта |
| Автор контента / редактор | Тексты, инструкции и информационные материалы |
| Исследователь | Изучение предметной области, гипотез и результатов исследования |

Это предлагаемый справочник StudyMate. Команда утверждает его состав до реализации.

В него **не включаем** руководителя, владельца проекта, автора проекта и другие обозначения управленческих прав. Права на управление возникают при создании проекта, а выбор желаемой роли их не предоставляет.

Настройки поля:

- Подпись: «Желаемая роль».
- Элемент: выпадающий список с одним выбранным значением.
- Начальное состояние: «Не указана».
- Подсказка: «Выберите, какие задачи вы хотите выполнять в команде».
- Пользователь может изменить или очистить выбор.
- Свободное создание роли через форму профиля недоступно.
- Сервер принимает только существующее доступное значение справочника.
- Поле видно всем зарегистрированным студентам, если заполнено.

**Связь с заявкой:** желаемая роль в профиле — общее предпочтение. При отклике студент выбирает конкретную свободную роль проекта. Эти значения могут различаться. Изменение предпочтения не меняет ранее поданные заявки или роль в команде.

## 4. Обоснование остальных полей

| Поле | Зачем нужно | Что нельзя из него заключать |
|---|---|---|
| Имя и фамилия | Позволяют узнавать человека в профиле, заявке и команде | Профиль не подтверждает паспортную личность |
| Вуз | Даёт учебный контекст | Название вуза не подтверждает уровень навыков |
| Специальность | Показывает направление подготовки | Не заменяет конкретные компетенции |
| Курс | Показывает этап обучения | Не определяет опыт и свободное время |
| Навыки | Позволяют понять заявленные умения студента | Теги не означают проверенную квалификацию |
| О себе | Позволяет пояснить опыт, цели и готовность учиться | Свободный текст не является объективной оценкой человека |

Обязательность вуза, специальности и курса сохраняем из действующей US-02. Эти сведения не должны автоматически увеличивать оценку кандидата.

## 5. Правила заполнения

### Имя и фамилия

- Обязательно указать и имя, и фамилию; поле отмечается звёздочкой.
- Пустое значение и строка из пробелов отклоняются с сообщением «Заполните обязательное поле».
- В общем поле должны быть как минимум две содержательные части, разделённые пробелом. Одного имени или одной фамилии недостаточно; сообщение: «Укажите имя и фамилию». Составные имена и фамилии допускаются.
- Отчество не требуется.
- Нельзя требовать ровно три слова или только кириллицу.
- Для ещё не заполненного профиля при отсутствии имени в карточке показывается «Студент»; это не позволяет сохранить профиль без имени и фамилии.
- Email вместо имени не показывается.

### Вуз и специальность

- В MVP используются обычные текстовые поля.
- Пустое значение и строка из пробелов отклоняются.
- Подтверждение обучения и отдельные справочники учебных заведений пока не реализуются.
- Ошибка при отсутствии значения: «Заполните обязательное поле».

### Курс

- Пользователь выбирает значение самостоятельно; курс заранее не подставляется.
- Допускаются только целые значения от 1 до 6.
- Некорректное значение отклоняется сервером.
- Сообщение: «Укажите корректный курс обучения».

### Навыки

- Выбираются из единого справочника, общего с требованиями проектов.
- Требуется хотя бы один навык.
- Максимум — 15 суммарно, включая hard и soft skills.
- Отдельно обязательный hard skill и обязательный soft skill не требуются.
- Повторы запрещены.
- Уровни владения, оценки и подтверждения в MVP не входят.
- Пользователь может удалить выбранный навык, но сохранить пустой набор нельзя.

### О себе

- Пустое значение разрешено.
- Под полем показывается счётчик символов.
- Максимальная длина — 1000 символов.
- Сервер отклоняет превышение; текст не обрезается незаметно.
- Пользовательский HTML не выполняется.

### Общие правила

1. Изменять значения может только владелец.
2. Все ограничения проверяются сервером.
3. При ошибке введённые значения остаются в форме.
4. Некорректная форма не сохраняется частично.
5. Очистка необязательного поля удаляет прежнее значение после сохранения.
6. Новых ограничений на отклик из-за отсутствия желаемой роли не добавляем.

## 6. Видимость профиля

Профили доступны всем авторизованным студентам. Автор проекта просматривает их на тех же условиях.

В MVP видимость фиксированная: пользователь не настраивает аудиторию отдельных полей.

| Данные или действие | Владелец | Другой зарегистрированный студент | Автор проекта | Неавторизованный посетитель |
|---|---|---|---|---|
| Имя и фамилия | Видит | Видит | Видит | Не видит |
| Вуз, специальность, курс | Видит | Видит | Видит | Не видит |
| Навыки | Видит | Видит | Видит | Не видит |
| Желаемая роль | Видит | Видит, если заполнена | Видит, если заполнена | Не видит |
| О себе | Видит | Видит, если заполнено | Видит, если заполнено | Не видит |
| Редактирование профиля | Может | Не может | Не может | Не может |
| Email и служебные данные аккаунта | В собственных настройках | Не видит | Не видит | Не видит |

Перед сохранением формы показывается пояснение:

> Сведения вашего профиля будут доступны всем зарегистрированным студентам StudyMate. Email и пароль в профиле не отображаются.

Дополнительные правила:

- Неавторизованному посетителю предлагается войти.
- После входа пользователь может вернуться к запрошенному профилю.
- В чужом профиле отсутствует кнопка «Редактировать».
- Прямой запрос на изменение чужого профиля отклоняется сервером.
- Право управлять проектом не даёт права менять сведения кандидата.
- Заявки, сопроводительные письма и статусы откликов не становятся частью общедоступного профиля.
- Незаполненный профиль отображается без ошибки: «Студент», заглушка аватара и сообщение «Пользователь пока не заполнил профиль».

## 7. Путь владельца профиля

1. Студент регистрируется или входит в систему.
2. После регистрации открывается заполнение профиля; при повторном входе профиль доступен через навигацию.
3. Пользователь видит обязательные поля и пояснение видимости.
4. Обязательно указывает имя и фамилию, вуз, специальность, курс и навыки.
5. При желании выбирает специализацию и добавляет описание.
6. Нажимает «Сохранить».
7. Сервер проверяет значения и права.
8. При успехе открывается карточка с сообщением «Профиль успешно обновлён».
9. После обновления страницы и повторного входа данные сохраняются.

При редактировании форма содержит текущие значения. Отмена с изменениями вызывает предупреждение с действиями «Остаться» и «Выйти без сохранения».

## 8. Путь другого студента и автора проекта

1. Авторизованный пользователь переходит по ссылке на профиль студента.
2. Видит основные сведения, навыки, желаемую роль и описание.
3. Может понять заявленные умения и предпочтения человека.
4. Не получает возможности редактирования.

Если профиль открывается из заявки, автор проекта изучает карточку и возвращается к рассмотрению заявки. Принятие и отклонение выполняются в сценарии заявок.

Отдельный каталог студентов и поиск людей в этот MVP не добавляем. Необходимы страница профиля и переходы из уже реализованных мест, где показывается студент.

## 9. Критерии приёмки

MVP готов, когда:

- Владелец сохраняет и редактирует свой профиль.
- Имя и фамилия обязательны при сохранении профиля; пустое значение, строка из пробелов и значение только из одной части отклоняются сервером с понятной ошибкой.
- Ошибка имени и фамилии не стирает введённые данные и не приводит к частичному сохранению формы.
- Регистрация остаётся доступной по email и паролю без предварительного заполнения профиля.
- Данные сохраняются в PostgreSQL и остаются после повторного входа.
- Желаемая роль выбирается из справочника, меняется и очищается.
- В справочнике нет роли руководителя или владельца проекта.
- Выбор специализации не предоставляет управленческих прав.
- Другой зарегистрированный студент может прочитать профиль.
- Автор проекта может прочитать профиль кандидата.
- Неавторизованный посетитель не получает сведения профиля.
- Чужое редактирование запрещено, включая прямые запросы.
- Email, заявки и письма не раскрываются в карточке.
- Ограничения полей проверяются сервером.
- Ошибки не стирают введённые данные.

Приоритет реализации: **сохранение профиля → просмотр зарегистрированными студентами → желаемая роль → переход к карточке из существующего сценария заявок**.
